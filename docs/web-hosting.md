# 웹 호스팅 배포 기록

Firebase Hosting(프로젝트 `pilateacher`)의 배포 이력과 도메인 연결 절차를 남긴다.

대표가 PC 에서 터미널을 켜지 않고 주소만 쳐서 앱을 쓰기 위한 것이다. 이관·발급·급여
집계는 폰보다 PC 가 편한 일인데, 그 앞에 개발 도구가 놓여 있었다.

배포는 저장소 루트에서 다음 한 줄로 한다.

```bash
npm run deploy:web
```

PowerShell·Git Bash 어디서든 같다. 이 한 줄이 `npm run build`(prebuild 로 타입
검사·린트·테스트) → `firebase deploy --only hosting` 을 순서대로 돌리므로, 테스트가
깨진 채로 나가는 빌드가 나올 수 없다.

배포 직후 주소는 아래 둘이다. 둘은 같은 내용을 가리킨다.

- `https://pilateacher.web.app`
- `https://pilateacher.firebaseapp.com`

## 무엇이 설정되어 있는가

`firebase.foundation.json` 의 `hosting` 블록이다.

- **public `dist`** — Vite 빌드 산출물
- **rewrites `**` → `/index.html`** — SPA fallback. 이것이 빠지면 새로고침이나
  주소 직접 입력이 404 가 된다. 그 증상은 배포한 사람이 아니라 대표가 만난다.
  `npm run deploy:web` 이 배포 전에 이 규칙이 있는지 확인하고, 없으면 멈춘다.
- **헤더** — 기본이 "캐시하지 않는다" 이고, 이름에 해시가 붙는 `assets/` 만 1년
  캐시한다. 겹치는 규칙은 뒤에 오는 것이 이기므로 순서가 곧 뜻이다.

  `/index.html` 만 지정하면 안 된다. SPA 는 `/members/abc` 같은 주소도 index.html 을
  받는데 그 주소들은 기본값(1시간)으로 캐시되고, 배포가 한 시간 동안 사용자에게
  닿지 않는다. 첫 배포에서 실제로 그랬다 — `/` 가 `max-age=3600` 으로 나왔다.

  `sw.js` 도 캐시하면 안 된다. 새 배포가 옛 워커에 막혀 화면이 갱신되지 않는다.

## 사용자 지정 도메인 — pilateacher.com

Firebase 콘솔에서 하는 일과 도메인 등록업체에서 하는 일이 나뉜다.

### 1. Firebase 콘솔에서 도메인을 추가한다

1. [Firebase 콘솔](https://console.firebase.google.com/project/pilateacher/hosting/sites) → **Hosting**
2. **사용자 지정 도메인 추가**
3. `pilateacher.com` 을 입력하고 계속

### 2. 소유권을 증명한다

Firebase 가 **TXT 레코드** 하나를 보여준다. 값은 프로젝트마다 다르므로 화면에 뜬
것을 그대로 쓴다 — 이 문서에 적어 두지 않는 이유가 그것이다.

도메인을 산 곳(가비아·후이즈·Cloudflare·GoDaddy 등)의 **DNS 관리** 화면에서 추가한다.

| 유형 | 호스트 / 이름 | 값 |
| --- | --- | --- |
| TXT | `@` (또는 비움) | Firebase 가 보여준 `google-site-verification=...` |

호스트 칸의 표기는 업체마다 다르다. `@`, 비움, `pilateacher.com` 중 하나이고,
업체 도움말이 "루트 도메인" 이라고 부르는 것이다.

추가한 뒤 Firebase 화면에서 **확인** 을 누른다. DNS 전파에 보통 몇 분, 늦으면
몇 시간이 걸린다.

### 3. A 레코드를 추가한다

소유권이 확인되면 Firebase 가 **A 레코드 두 개**를 보여준다. 둘 다 추가한다.

| 유형 | 호스트 / 이름 | 값 |
| --- | --- | --- |
| A | `@` | Firebase 가 보여준 첫 번째 IP |
| A | `@` | Firebase 가 보여준 두 번째 IP |

IP 는 Firebase 가 바꿀 수 있으므로 화면에 뜬 값을 쓴다.

`www.pilateacher.com` 도 쓰려면 Firebase 에서 도메인을 하나 더 추가하고, 그때는
보통 CNAME 을 준다.

| 유형 | 호스트 / 이름 | 값 |
| --- | --- | --- |
| CNAME | `www` | `pilateacher.web.app` |

### 4. 기다린다

Firebase 가 Let's Encrypt 인증서를 자동으로 발급한다. **보통 몇 시간, 최대 24시간**
걸린다. 그동안 콘솔의 상태가 `보류 중` → `연결됨` 으로 바뀐다.

인증서가 나오기 전까지 `https://pilateacher.com` 은 경고를 띄운다. 정상이고, 기다리면
된다. 그 사이에는 `https://pilateacher.web.app` 을 쓰면 된다.

### 막히면 볼 것

- **소유권 확인이 계속 실패한다** — TXT 를 서브도메인(`_firebase.pilateacher.com`)에
  넣은 경우가 많다. 루트에 넣어야 한다.
- **A 레코드를 넣었는데 옛 사이트가 뜬다** — 등록업체의 기본 파킹 페이지가 A 레코드로
  남아 있는 경우다. 기존 A 레코드를 지우고 Firebase 것만 남긴다.
- **`www` 만 되고 루트가 안 된다** — 루트에는 CNAME 을 쓸 수 없는 업체가 많다.
  루트는 A 레코드, `www` 는 CNAME 이다.

## 웹에서 되는 것과 안 되는 것

Capacitor 앱과 웹은 같은 코드를 쓴다. 네이티브 플러그인은 웹 구현이 있는 것과
없는 것이 갈린다.

| 기능 | 웹에서 | |
| --- | --- | --- |
| 이관 · 발급 · 급여 집계 · 회원 관리 | 된다 | PC 로 하려던 바로 그 일들 |
| 사진 촬영 | 된다 | `getUserMedia` 로 붙는다. 네이티브 미리보기 대신 브라우저 카메라 |
| 사진 저장 · 공유 | 된다 | 플러그인이 없으면 브라우저 다운로드·공유로 내려간다 |
| 햅틱 | 조용히 무시된다 | 진동이 없을 뿐 오류가 아니다 |
| **음성 수업기록** | **안 된다** | 아래 참고 |

### 음성 수업기록이 웹에서 안 되는 이유

서버 녹음 엔진은 `@capgo/capacitor-audio-recorder` 를 쓰고, 그 플러그인에는 웹
구현이 없다. 브라우저에서는 `checkPermissions()` 부터 "not implemented" 로 던진다.

**고치기 전에는 그 실패가 권한 문제로 읽혔다.** 실패를 잡아 `null` 로 만들면
`nativeAudioPermissionState(null)` 이 `prompt` 를 돌려주기 때문이다. 그래서 PC
브라우저에서 "말하기를 사용하려면 마이크 권한을 허용해 주세요" 가 뜨고, 허용해도
아무 일이 일어나지 않았다. 강사는 자기 브라우저 설정을 뒤지게 된다.

지금은 플러그인에 묻기 전에 가르고, 화면이 이렇게 말한다.

> 음성 수업기록은 폰 앱에서만 됩니다. 이 화면에서는 직접 입력으로 기록해 주세요.

웹에서 `MediaRecorder` 로 녹음을 살릴 수는 있다. 그러지 않은 이유는 같은 기능에
코드 경로가 둘이 되기 때문이다 — 업로드 형식·무음 판정·중단 복구가 각각 따로
움직이고, 음성 기록은 이 앱에서 가장 많이 깨졌던 자리다. PC 는 이관·발급·급여
집계를 하러 켜는 화면이고 수업기록은 폰에서 쓴다.

판정과 문구는 `src/features/voice/web-support.js` 에 있고,
`tests/voice/web-support.test.js` 가 순서까지 고정한다 — 플러그인에 먼저 물으면
그 실패가 다시 권한 문제로 읽힌다.

## 개발 모드 서비스 워커

`npm run dev` 에서는 서비스 워커를 **등록하지 않고, 이미 등록된 것이 있으면
걷어낸다.** 코드를 고쳐도 화면이 안 바뀌는 일이 반복됐고, 한 번 등록된 워커는 dev
서버를 껐다 켜도 살아 있어서 등록을 멈추는 것만으로는 이미 걸린 사람이 풀려나지
않는다.

네이티브 앱에서도 걷어낸다 — 자기 자산을 자기가 들고 있는데 그 위에 워커가 끼면
앱을 새로 깔아도 옛 화면이 남는다.

프로덕션 웹에서만 등록한다. 판정은 `src/features/ui/service-worker.js` 에 있다.
